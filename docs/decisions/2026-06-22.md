# Decisions: 2026-06-22

## Agent Governance Foundation

Decision: add the first governed vertical slice for an agent control plane as contracts, schemas, fixtures, reusable validation, tests, and docs.

Accepted boundaries:

- `contracts/agent-governance/` is canonical for policy, source authority, router, capability, personas, workflow, loop, and hook policy.
- `contracts/schemas/agent-*.schema.json` defines strict JSON Schema 2020-12 shapes.
- `packages/core/` owns reusable validation, including cross-reference and semantic fail-closed checks.
- `scripts/agent/validate-governance.ts` is a thin local CLI over core validation.
- `tests/governance/` and `tests/security/` prove governance and security invariants.

Deferred:

- live hook adapters
- loop runner
- context-pack generator
- receipt writer
- generated run state
- learning distillation
- scheduled automation
- connector, merge, release, deploy, or other external-write automation

Rationale: the scaffold should absorb portable governance primitives without copying client-specific operating content or creating a competing runtime governance system. Contracts remain canonical and runtime adapters remain downstream.

## Assignment and Runtime Evidence Contracts

Decision: add assignment, context-profile, and receipt-policy contracts as the next non-automated layer.

Accepted boundaries:

- Assignments bind route, workflow, personas, autonomy, paths, requested actions, checks, approvals, and receipt requirements.
- Context profiles declare bounded source selection and sensitive path denials, with stale detection requirements.
- Receipt policy declares transient storage, audit promotion, privacy, and required receipt fields.
- `scripts/agent/validate-assignment.ts` validates a task assignment against canonical governance.

Deferred:

- context-pack generation
- receipt writing
- run-state persistence
- hook adapters
- loop execution
- scheduled automation

Rationale: copied projects need structured task intake and evidence boundaries before any runtime automation can be made safe.

## Local Runtime Evidence and Adoption Layer

Decision: add local-only lifecycle helpers that make a governed agent run inspectable without enabling live automation.

Accepted boundaries:

- `agent:run-init` creates assignment JSON, assignment markdown, context pack, and run manifest together.
- Run manifests link assignment, context pack, route, branch, git revision, and source hashes.
- `agent:check-context` detects stale context against the manifest.
- `agent:receipt` drafts schema-valid receipts from assignment/context/git state and requires an audit reason for promotion to `docs/audits/`.
- Assignments support task type, owner/reviewer, do-not-touch paths, dependencies, and blockers.
- `scaffold:adoption-check` validates generated-repo governance placeholders.
- Hook scripts remain adapter-neutral, opt-in, and disabled by default.
- `agent:run-loop` is manual-only, bounded, requires a manifest and verifier command, and writes a stop receipt.
- Learnings are advisory contract artifacts and cannot override canonical contracts.

Deferred:

- live hook adapters
- scheduled execution
- connector, merge, release, deploy, or other external-write automation
- hidden global tool enforcement

Rationale: the scaffold should become usable as a project-agnostic framework while keeping authority local, inspectable, and contract-bound.

## Role Catalog And Specialized Personas

Decision: add beginner-friendly task routing for code, docs, tests, copy, and research so non-expert users can get consistent agent behavior without understanding the full governance graph.

Accepted boundaries:

- `docs/agents/ROLE_CATALOG.md` is the human-facing role picker.
- `docs-steward`, `copywriter`, `researcher`, and `qa-reviewer` personas specialize behavior while using the existing local authority boundary.
- Matching repo-local skills keep role instructions short and portable across agent harnesses.
- Router task types select specialized makers for docs, content, research, and test work.
- Personas guide behavior; contracts, assignments, policy, and validation still govern authority.

Deferred:

- harness-specific activation logic
- live external research adapters
- brand, legal, release, or external publishing approval automation

Rationale: the scaffold should help a non-expert feel operationally confident while keeping the process lightweight, explicit, and auditable.

## Review-Only Cleanup And Human Copy Skills

Decision: add reusable skills for desloppify cleanup scanning and human-sounding copy review.

Accepted boundaries:

- `desloppify-review` creates or updates `DESLOPPIFY.md` as a prioritized backlog.
- Desloppify work is review-only until the user selects a cleanup task.
- `quality` task routing selects `quality-reviewer` with A1 autonomy.
- `human-copy-review` helps copy sound natural while preserving source-backed claims.
- Copy and quality skills remain repo-local and portable across agent harnesses.

Deferred:

- automatic cleanup task execution
- broad refactors without user selection
- publishing or brand/legal approval automation

Rationale: quality-control and human-copy review should be easy to ask for, but they must not create hidden permission to rewrite the project.

## Routed Memory And Drift Checks

Decision: adopt lightweight memory discipline from routed-context and loop-engineering patterns without adding autonomous triggers or heavy runtime dependencies.

Accepted boundaries:

- `AGENTS.md` and `REPO_PROFILE.json` stay small anchors.
- `docs/agents/CONTEXT_ROUTING.md` routes agents to task-specific context.
- `LOG.md` is a compact work feed, not a replacement for decisions, receipts, or audits.
- `docs/governance/ARTIFACT_TIMELINE_CONVENTION.md` defines optional append-only timelines for durable artifacts.
- `npm run scaffold:memory-check` catches broken links, missing scripts, undocumented routes, and missing skills without spending model tokens.
- `pattern-capture` is used only after a pattern is repeated or clearly cross-project.
- `worktree-shipping-checklist` captures branch/worktree hygiene without binding the scaffold to one agent harness.

Deferred:

- autonomous sync
- scheduled memory watchers
- telemetry
- mandatory domain or task folders before a copied project earns them

Rationale: persistent agent memory is valuable only when it stays routed, checkable, and cheap to maintain.
